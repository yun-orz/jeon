# G5冻结模型的上下文边界诊断

本阶段属于“Jeon光学编码复现＋基础重建验证”，不训练、不调整模型、不切换DOE，不是新的盲测或完整论文复现。

## 运行

PyCharm解释器用D:\dev\python\python3.10.4\python.exe，打开本工程，直接运行main_g5_boundary.py。依赖沿用requirements_g3.txt；已安装环境为CPython3.10.4、NumPy2.2.6、SciPy1.15.3、Matplotlib3.10.9、PyTorch2.14.1+cpu。CPU默认4线程；不需GPU、Notebook、Docker、Harness或聊天状态。相对路径按入口位置解析。

config_g5_boundary.json集中指定冻结复测run/审核、数据目录、context_sizes=[128,160,192,256]、support_size=352、诊断阈值0.01、保存/显示开关。命令行可用--no-save只读复算、--show-plots尝试弹窗；实际人工GUI操作须另行验证。新结果保存results/g5_boundary/run_*，不覆盖旧文件。

## 为什么共享测量

相机看到的是场景经过PSF扩散后的强度。若分别把物体裁成128和256再各自编码，两幅输入的边缘光通量也变了，无法仅凭输出差异判断解码器的边界影响。本实验先从同一352×352完整有效物体支持域生成RGB测量，再中心裁出各尺寸输入。97×97核半径48像素，最大256观测域离352支持边界也是48像素，因此所有观测像元所需的物体贡献都在支持域内；与无限域等价仅针对这张已截断97像素PSF及局部支持，不代表真实PSF无限尾部已验证。

同一固定32×32中心目标、原光谱尺度、校正、25波段、通光效率、合成RGB响应均不变。输入是每波段相对光子量，强度线性叠加，无噪声/CFA/gamma。支持域数据先float32换算，精确G2算子float64编码，再float32送网络，沿用前阶段协议。U-net池化有位置相位，因此各上下文中心偏移必须是8像素整数倍，避免改变池化网格位置。

原四块逐一检查352支持范围；越界、掩码无效或负/非有限谱明确记录排除，绝不补零无效像元或另选高分区域。只对接受的原块比较，不能把三块结果与之前四块总指标直接比较。还保存同三块的旧128预测、旧测量，以及共享测量128预测之间差异，区分更换外部物体支持和更换解码范围的影响。旧测量中心32因halo48足够，理论上保持一致；外围观测不一定相同。

## 如何解释结果

每个尺寸都保存中心PSNR/SSIM/SAM，并计算与最大256结果和相邻尺寸的相对L2差、RMSE、最大绝对差。指标沿用G5固定L=1、valid高斯SSIM、未裁剪SAM。相对L2定义为||小域预测−参考预测||₂/||参考预测||₂；参考零范数写null。

默认最后192→256变化小于1%仅是工程诊断阈值，不是论文标准，且不能证明整幅图像或任意大域已收敛。若不满足，应记录失败，不能调阈值让结果通过。图像变化小也不证明光谱正确；物理尺寸、实测响应、网络和训练协议缺口仍存在，paper_alignment_passed=false，暂不进入G6。

## 保存与验证记录

arrays/boundary.npz保存支持域目标/共享RGB、各尺寸输入、中心预测、同三块旧预测/旧测量、核/响应/波长。metrics保存逐块/逐波段原始指标、汇总和差异；figures保存曲线和同尺度中心对比。dataset_manifest记录接受/排除原因，source_manifest和source_evidence保留SHA；保存数组逐元素重载核对。
