# Goal 任务交接

本目录恰好包含 M0–M7 八份独立任务。将相应任务全文交给 Goal 模式；先读本文件、任务中要求的前置报告、`protocol.json`、`contracts.json` 和 `parameter_evidence.json`。M0 的实际验收位置见入口目录的 `m0_index.json`。

默认 Python 为 `D:/dev/python/python3.10.4/python.exe`；GPU 安装后的训练解释器为 `D:/PyCharmProjects/Jeon2019/work/environments/jeon_gpu_cu121/Scripts/python.exe`。本文中 `<入口>` 均指 `D:/PyCharmProjects/Jeon2019/outputs/jeon2019_optics/reproduction_v1/main.py`。尖括号参数是待用实际验收路径替换的变量，不能当作已存在文件执行。

所有任务共用以下边界：

1. 仅完成该里程碑；M6 每次仅执行指定器件、指定 epoch 区间或最多8小时。不得自动进入下一里程碑。
2. 代码、数据、结果只放协议指定的新目录。历史 G0–G5 源码、数据、模型、run、审核证据和原 CPU 环境只读。`CURRENT_STATUS.md` 只追加。GPU环境、官方安装包续传记录是M1明确授权的例外，不纳入历史不可变清单。
3. 不删除文件、不清空大段内容，不清理缓存目录或旧 checkpoint；任何删除先问用户并取得明确同意。安装器如需替换该新环境内文件属于M1安装步骤；若准备主动删除已有安装或下载文件，仍先征求同意。
4. 每次执行先检查剩余空间和实际预计新增占用；不足则记录需求、可恢复入口和准确状态后停止，不自行改用其他盘或降低数据规模来冒称通过。
5. 检查失败保留证据，不放宽阈值。预算停止仅表示本次有界执行交付，不能把该里程碑写成完成。保存失败不生成伪完成标记。
6. 每项交付包含中文报告、实际命令、有效配置、输入/输出SHA、关键数值、失败记录、逐项验收、恢复命令、下一阶段输入。使用 `contracts.json` 的报告字段；`paper_alignment_passed` 始终为 false，除非取得缺失作者信息并单独审核。
7. 从任意工作目录执行入口必须使用同样的入口相对路径解析。M0 已实现 `check`（无参数默认）及 `report`；其余子命令由相应里程碑实施，目前必须明确拒绝，不能生成成功占位产物。

顺序为 M0 → M1/M2 → M3 → M4 → M5 → M6 → M7。M2 不依赖GPU；M3批量下载需空间预检。进入下一阶段前核对前置报告的 `status=passed` 与实际文件指纹，不能仅靠任务文件或历史工程通过记录判断已完成。

M6 可多次使用同一任务，例如：Jeon 0–10 → 10–20 → 20–30 → 30–40，再按同样区间执行 Fresnel。若8小时结束仍未到区间终点，下一次继续同一区间，不能跳过剩余 epoch。
