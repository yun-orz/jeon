# M3：多数据集流水线与封存测试集

目标：形成场景独立、波长正确、按需读取的正式数据版本。依赖M0、通过的M2物理算子包；GPU非必要。只写新代码、新数据和新M3结果。批量下载前必须重新检查D盘空间，不能自行清理或移盘。

输入：官方Harvard/ICVL/KAIST来源、实际元数据、M0默认数量/划分及场景种子20261006。作者精确子集未知；文中238与排除10有歧义，采用声明的新名单。历史img3/img4/img5保留诊断，不用于新测试选择；在冻结前明确其关联组是否纳入正式训练，不能把已看场景归入新封存测试。

实施：

1. 新入口实现 `data`，分离下载、元数据审核、预处理、划分、训练尺度/增益拟合和索引生成。下载有断点、文件SHA和内容校验。先估算实际压缩/解压/预处理/缓存需求及checkpoint保留空间；不足保存状态并停止。
2. Harvard读取ref/lbl/calib及有效掩码，确认校正和相对能量语义；ICVL按实际发布波长选420–660nm，确认相对辐亮度语义；KAIST EXR按通道名称映射波长，保留反射率，不按数组序号猜测。格式/通道不符明确失败，不能补零假装完整。
3. 以稳定场景及相关场景组ID建立清单，原始SHA和近重复/同场景曝光核对。种子与组ID哈希排序选择目标58/150/30；按组划分52/6、135/15、16/4/10。组和重复检查优先，不足报告实际规模，不从测试补足；单纯随机文件划分不可通过。
4. 预先登记Harvard/ICVL的共同尺度估计器、有效像元规则和相对能量约定，仅用训练集各拟合一个尺度；KAIST不拟合尺度。跨数据集尺度是实施假设，不称绝对标定。禁止逐图、逐波段或测试拟合。使用两个器件同一训练集共同测量增益；登记拟合算法并生成绑定数据版本的最终算子包，不改M2物理来源。
5. 场景划分后基础图像半尺寸，与49×49/12.44µm算子一致；另记录0.5/1/2增强。生成30000条256×256索引，不复制30000个完整patch文件。索引记录场景、尺度、坐标、有效mask、种子和预处理版本。
6. 按需读取、在线增强、单场景有界缓存≤512MiB；测量真实峰值缓存，过大场景使用分块/内存映射，不能先把整个数据集载入内存再宣称有界。
7. 冻结不可变测试清单。在M7前测试只能核对文件、通道、完整性及重复元数据，不能生成预测、成绩、选择ROI或用于拟合尺度。对管线测试使用训练/合成fixture。
